# Спецификация состояний и тестовых сценариев (черновик)

Этот документ предназначен для реализации STM32 в Codex. Он не заменяет проверку аппаратуры и `my_pixhawk.ino`.

## 1. Источники требований
- **Из обсуждений:** три положения SWC: ручное управление, сохранение точки, движение к точке.
- **Из обсуждений:** во время миссии при потере связи продолжать миссию, мигать габаритами; после окончания при отсутствии связи ждать 90 с и идти HOME; завершённую миссию при восстановлении связи автоматически не повторять.
- **Из обсуждений:** GPS на STM32, ESP32 — мост.
- **Не установлено:** какая именно связь учитывается в правиле потери связи, какие физические входы используются, условия GPS fix, низкое напряжение, приоритеты между режимами.

## 2. Состояния (предлагаемая архитектура)
| Состояние | Назначение | Входное событие | Условие выхода |
| --- | --- | --- | --- |
| BOOT | Самотестирование, запрет самопроизвольной тяги | Подача питания/сброс | Валидные RC и аппаратные условия |
| MANUAL | Ручное управление | SWC=1 при валидном RC | Подтверждённая команда режима |
| SAVE_POINT | Однократное сохранение координат | Событие перехода в SWC=2 | Сохранено/ошибка; дальнейший режим TBD |
| TO_POINT | Навигация к выбранной точке | SWC=3 и подтверждённая точка | Достигнута цель/отмена/ошибка |
| MISSION | Выполнение маршрута | Команда миссии, источник TBD | Завершена/отменена/ошибка |
| LINK_LOST_MISSION | Миссия выполняется при потере определённого канала связи | Потеря связи во время MISSION | Завершение миссии или восстановление связи (поведение TBD) |
| WAIT_LINK | Ожидание связи после завершения миссии | Миссия завершена, связи нет | Связь восстановлена или прошло 90 с |
| HOME | Переход к домашней точке | Истёк таймер ожидания при отсутствии связи | Дом достигнут/ошибка |
| ERROR | Безопасное состояние при неисправности | Критическое событие | Условия восстановления TBD |

Названия состояний **не равны** числовым кодам `FLIGHT_MODE` из телеметрии; потребуется отдельная таблица отображения.

## 3. Переходы (только подтверждённая часть)
| Откуда | Событие | Куда | Действие |
| --- | --- | --- | --- |
| MANUAL | SWC переходит в SAVE | SAVE_POINT | Однократная попытка сохранения точки; критерии GPS TBD |
| MANUAL | SWC переходит в TO_POINT | TO_POINT | Начать переход только после проверки цели и безопасности |
| MISSION | Потеря согласованного канала связи | LINK_LOST_MISSION | Продолжать миссию; мигать габаритами |
| LINK_LOST_MISSION | Миссия завершилась, связи нет | WAIT_LINK | Запустить таймер 90 секунд |
| WAIT_LINK | Связь восстановилась до таймаута | TBD | Не перезапускать завершённую миссию |
| WAIT_LINK | Истекло 90 секунд и связи нет | HOME | Двигаться к HOME при валидной домашней точке и навигации |
| Любое | Потеря GPS, критическая батарея, аппаратный аварийный сигнал | TBD | Требует отдельного согласования; не придумывать |

## 4. Приоритеты событий (предложение для обсуждения)
1. Аппаратный аварийный останов/критическая неисправность.
2. Подтверждённый ручной перехват управления.
3. Навигационные аварии и ограничения безопасности.
4. Активная миссия и автономные правила.
5. Команды с Android.

Этот порядок **не утверждён**; прежде чем писать управляющий код, согласовать его.

## 5. Тестовая матрица
| ID | Исходное состояние | Воздействие | Ожидаемый результат | Статус |
| --- | --- | --- | --- | --- |
| T01 | MANUAL | SWC=2 | Одна попытка сохранить точку | Смысл согласован, детали TBD |
| T02 | MANUAL | SWC=3, точка выбрана | Переход к точке | Смысл согласован, условия TBD |
| T03 | MISSION | Пропала связь | Продолжение миссии + мигание габаритов | Требование известно; канал TBD |
| T04 | LINK_LOST_MISSION | Миссия завершена, связи нет | Начать ожидание 90 с | Требование известно |
| T05 | WAIT_LINK | 90 с прошло, связи нет | HOME | Требование известно, безопасность TBD |
| T06 | WAIT_LINK | Связь восстановлена | Завершённая миссия не возобновляется | Требование известно |
| T07 | MANUAL | Пропал RC | TBD | Требует решения |
| T08 | TO_POINT | Пропал GPS | TBD | Требует решения |
| T09 | Любое | Низкое напряжение | TBD | Требует решения |
| T10 | BOOT | SWC сразу в позиции автопилота | Не допускать неожиданного старта | Предлагаемое требование |

## 6. Задачи Codex
1. Не писать полноценный алгоритм управления до согласования неопределённых переходов.
2. Найти/получить `my_pixhawk.ino`, если он доступен, и извлечь RC-каналы, кодирование i-BUS и выбор точки.
3. Реализовать чистую, тестируемую модель состояний без зависимости от железа.
4. Добавить юнит-тесты T01–T10, помечая TBD как пропущенные до решения.
5. Сформировать список вопросов для владельца проекта по всем TBD.
