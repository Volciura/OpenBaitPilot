# Анализ `my_pixhawk(1).ino` — фактическое поведение

Источник: пользовательский файл `my_pixhawk(1).ino`, 858 строк. **Никакие исходники Runferry не использовались.**

## Важное разграничение
Это **прошивка Arduino Mega — MAVLink/i-BUS мост для Pixhawk**, а не готовый автономный автопилот STM32. В ней нет алгоритма удержания курса или расчёта рулевого воздействия. STM32 должен реализовать управление самостоятельно. Совпадение с желаемой схемой переключателей НЕ подтверждено.

## Реальные каналы из обработчика `MAVLINK_MSG_ID_RC_CHANNELS_RAW`
| Канал | Порог | Действие |
| --- | --- | --- |
| CH4 | `>1700` | Увеличить выбранный номер точки с циклом 0–9 |
| CH4 | `<1300` | Уменьшить выбранный номер точки с циклом 0–9 |
| CH5 | `>1700` | Однократно сохранить текущие GPS координаты (`RC_5_EXECUTED`) |
| CH6 | `>1700` | Однократно вызвать `uploadMission()` (`RC_6_EXECUTED`) |
| CH6 | `>1700` | Одновременно устанавливает `RC_8_IS_DELIVERY=false` |
| CH6 | `<=1700` | `RC_8_IS_DELIVERY=true` |

**Несоответствие:** комментарии в начале файла называют RC7/RC8 и SWA/SWB/SWD, но рабочая логика использует CH4/5/6. Кроме того, CH6 повторно используется для режима доставки; вероятна ошибка, требующая проверки. Код **не реализует** заявленное ранее управление SWC тремя положениями. Новую схему SWC нужно согласовать отдельно.

**Риск:** CH4 увеличивает/уменьшает номер при каждом полученном сообщении, без edge detection и debounce. CH5/CH6 защищены флагами однократного исполнения.

## Точки
- Массив `WP_LIST[10]`, индексы **0–9**.
- **Точка 0 — HOME**, 1–9 — пользовательские точки.
- `STARTING_EEPROM_ADDRESS=17`; `EEPROM.get/put` хранит весь массив.
- Координаты — `int32_t` широта/долгота в **градусах × 10^7**.
- `saveCurrWP()` сохраняет выбранную точку; если выбран 0, вызывает `saveHome()`.
- Нет явной проверки GPS fix, возраста координат и допустимости (0,0) перед записью. Для STM32 нужны проверки.

## Миссия, которую формирует старый код
`mission_count()` сообщает **9 элементов** (seq 0..8):
| seq | MAVLink действие | Назначение |
| --- | --- | --- |
| 0 | `NAV_WAYPOINT` | HOME (точка 0) |
| 1 | `DO_CHANGE_SPEED` | Установка скорости |
| 2 | `CONDITION_DISTANCE` | Условие расстояния (по коду проверить значение) |
| 3 | `DO_CHANGE_SPEED` | Смена скорости |
| 4 | `NAV_WAYPOINT` | Выбранная точка |
| 5 | `DO_REPEAT_SERVO` | Сервопривод |
| 6 | `CONDITION_DELAY` | Задержка **30 с** |
| 7 | `DO_CHANGE_SPEED` | Смена скорости |
| 8 | `NAV_RETURN_TO_LAUNCH` | Возврат HOME |

Это описание **исторической миссии Pixhawk**, не готовый план новой STM32-реализации. Скорости и серво-параметры требуют дополнительной проверки по функциям `do_changeSpeed` и `do_servo`.

## Телеметрия i-BUS
Создаётся `iBUSTelemetry telemetry(10)`; сенсоры добавляются последовательно и обновляются раз в **500 мс**:
| Индекс | Тип сенсора | Значение из кода |
| ---: | --- | --- |
| 1 | `GPS_STATUS` | `gpsStateValues(selected_wp, satellites_visible)` |
| 2 | `ARMED` | `hb.base_mode` **целиком**, не нормализованный bool |
| 3 | `FLIGHT_MODE` | Таблица режимов ниже |
| 4 | `GPS_ALT` | `sonar_sendor` (по умолчанию 0, TODO; это НЕ фактическая GPS-высота) |
| 5 | `COG` | Сигнал обратной связи 500=успех, 1000=ошибка; потом сброс в 0 |
| 6 | `EXTV` | `sys_status.voltage_battery / 10` |
| 7 | `BAT_CURR` | `sys_status.current_battery` без пересчёта |
| 8 | `GROUND_SPEED` | `gps_raw_int.vel` без пересчёта |
| 9 | `GPS_DIST` | Расстояние в метрах от текущих координат до `WP_LIST[0]` |
| 10 | `GPS_LAT` | `gps_raw_int.lat` |
| 11 | `GPS_LON` | `gps_raw_int.lon` |

Точные бинарные идентификаторы, wire scale и checksum определяются библиотекой `iBUSTelemetry`, которой в файле нет. Не выдумывать их.

`FLIGHT_MODE` из констант: SAVE=0, HOME=1, WAIT=3, MANUAL=4, RETURN=5, RTL=6, CIRCLE=7, ERROR=8, TO_POINT=9; **2 отсутствует**.

`HEARTBEAT.custom_mode` → `FLIGHT_MODE`:
| custom_mode | FLIGHT_MODE |
| ---: | --- |
| 0, 1 | MANUAL (4) |
| 4 | WAIT (3) |
| 5 | CIRCLE (7) |
| 10 | TO_POINT (9) |
| 11 | HOME (1) |
| 12 | RTL (6) |

`ARMED` передаёт `hb.base_mode` без маскирования `MAV_MODE_FLAG_SAFETY_ARMED`.

При `sendOK_Failed(true)` выставляются `COG=500` и `FLIGHT_MODE=SAVE`; при false — `COG=1000`, `FLIGHT_MODE=ERROR`. `biper_COG_counter=2`, обновление каждые 500 мс; фактическая длительность импульса зависит от момента вызова.

## Потеря связи
**В загруженном коде нет реализации** обсуждённого правила «продолжать миссию, мигать габаритами, затем 90 секунд и HOME». Это отдельное требование новой прошивки; какой линк контролируется, нужно уточнить.

## Что Codex должен сделать
1. Реализовать независимую STM32 архитектуру без зависимости от Pixhawk/MAVLink, если мы отдельно не утвердим обратное.
2. Сохранить семантику точек 0=HOME, 1–9=точки и отображение телеметрии, если пользователь подтвердит совместимость.
3. Не переносить ошибки CH4 без debounce, CH6/RC8 и отсутствующие проверки GPS.
4. Согласовать SWC-переключение с пользователем: его нет в этом исходнике.
5. Составить тесты на выбор/запись точек, кодирование телеметрии, невалидный GPS, RC loss и завершение миссии.
