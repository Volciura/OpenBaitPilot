# Телеметрия: известные поля и совместимость с FlySky

## Происхождение
Из обсуждений существующего исходника **`my_pixhawk.ino`** (14.10.2026) известен следующий набор передаваемых полей. Автопилот передаёт телеметрию **в приёмник FlySky iA10B по i-BUS**, а не напрямую через тренерский разъём FS-i6.

> Это описание семантики из прежнего проекта, **не побайтовая спецификация**. Идентификаторы датчиков i-BUS, адреса, масштабирование, типы данных, CRC и реальная частота отдельных сообщений должны быть сверены с исходным кодом или захватом UART.

| Поле | Известное назначение | Что ещё проверить |
| --- | --- | --- |
| `GPS_STATUS` | Номер точки **0–9** и количество спутников | Упаковка двух значений, статус fix, кодирование |
| `FLIGHT_MODE` | Числовой код текущего режима | См. таблицу ниже |
| `ARMED` | Признак состояния armed | Условия установки/сброса |
| `COG` | В известных обсуждениях фигурируют значения **500/1000** | Что именно кодируют, единицы и масштаб |
| `GPS_ALT` | Высота GPS | Единицы, знак и масштаб |
| `EXTV` | Внешнее напряжение | Источник измерения и масштаб |
| `BAT_CURR` | Ток аккумулятора | Источник измерения и масштаб |
| `GROUND_SPEED` | Скорость относительно земли | Единицы и масштаб |
| `GPS_DIST` | Дистанция | До какой цели и в каких единицах |
| `GPS_LAT` | GPS широта | Представление и точность |
| `GPS_LON` | GPS долгота | Представление и точность |

**Ориентировочное обновление телеметрии — около 500 мс** в прежней реализации. Не считать это гарантией частоты для каждого поля.

## Значения `FLIGHT_MODE` (из ранее согласованной таблицы)
| Значение | Название |
| ---: | --- |
| 0 | `SAVE` |
| 1 | `HOME` |
| 2 | **не определено — не назначать без проверки** |
| 3 | `WAIT` |
| 4 | `MANUAL` |
| 5 | `RETURN` |
| 6 | `RTL` |
| 7 | `CIRCLE` |
| 8 | `ERROR` |
| 9 | `TO_POINT` |

В ранее обсуждавшемся коде также встречаются названия `MANUAL_M`, `SAVE_M`, `HOME_M`, `RETURN_M`, `RTL_M`, `CIRCLE_M`, `TO_POIUNT_M` (последнее написание сохранено как историческое). Нельзя автоматически считать эти имена и значения взаимозаменяемыми без просмотра исходника.

## Направления обмена
```text
STM32 ── i-BUS telemetry ──► FlySky iA10B ── radio ──► FS-i6
  │
  └── proposed data interface ──► ESP32 bridge ── Wi-Fi ──► Android
```

- i-BUS telemetry **от автопилота к приёмнику** — известная топология старой системы.
- Параллельное чтение этого потока ESP32 обсуждалось, но **электрическое подключение и способ разделения шины ещё не проверены**.
- Для STM32 ↔ ESP32 допустимо спроектировать отдельный протокол, но не менять смысл старых полей без явной версии.

## Экран FS-i6
- Пользователь хочет главный экран в стиле **Camarad**, используя при необходимости исходники прошивок FlySky.
- **Глубину на экран выводить не нужно.**
- Нужна совместимость с управлением точками, возвратом и режимами; конкретная компоновка дисплея и возможности существующей прошивки требуют проверки.
- Не предполагать, что данные телеметрии можно получить через стандартный тренерский PPM-разъём.

## План верификации
1. Получить `my_pixhawk.ino` и все зависимые файлы.
2. Найти места формирования `GPS_STATUS`, `FLIGHT_MODE`, `COG`, `GPS_DIST`, координат и питания.
3. Зафиксировать i-BUS sensor ID, длину, масштабирование, endian, периодичность и примеры пакетов.
4. Сопоставить значения на FS-i6 с логом на UART.
5. Написать тестовые векторы кодирования и декодирования.

## Результаты проверки исходника
См. `docs/source-audit-my-pixhawk.md` для точных индексов 1–11, источников значений и таблицы HEARTBEAT. В частности `GPS_ALT` занят заглушкой `sonar_sendor`, `ARMED` содержит `base_mode`, а `COG` используется для 500/1000 подтверждений.
